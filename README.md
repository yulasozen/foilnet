# FOILNET

A mesh-native graph neural network surrogate for ship hull hydrodynamics, trained on OpenFOAM CFD data.

## Result

![Predicted vs CFD surface pressure on a held-out hull](reports/figures/wigley_09_prediction.png)

Predicted vs. CFD surface pressure on `wigley_09`, a hull the model never saw during training (test R² = 0.984).

## What it does

CFD is accurate but slow — a single RANS solve on a hull mesh takes tens of minutes, which makes it impractical to use directly inside a design-optimization loop that needs thousands of evaluations. FOILNET trains a graph neural network to predict the steady-state surface pressure field on a hull directly from its geometry, treating the hull's surface mesh as a graph and each face as a node. Once trained, a forward pass replaces a full CFD solve, returning a pressure prediction in milliseconds instead of minutes. The tradeoff is accuracy at the edges of the training distribution, which this repo measures honestly rather than hides.

## Pipeline

1. **Parametric hull generation** — Wigley hulls sampled by Latin Hypercube Sampling over length `L`, beam ratio `B/L`, and draft ratio `T/L`.
2. **OpenFOAM CFD** — double-model (free-surface-free) RANS solve, k-ω SST turbulence, Re ≈ 1e6, run per hull in Docker.
3. **Mesh-to-graph conversion** — hull surface faces become graph nodes (position, normal, area — 7 geometry features per node), with solved surface pressure as the per-node target.
4. **HullGNN** — 4-layer GraphSAGE network mapping node geometry features + mesh connectivity to pressure.
5. **Prediction** — per-node pressure field, evaluated instantly against held-out hulls.

## Dataset

40 Wigley hulls generated by Latin Hypercube Sampling (seed 42) over `L ∈ [4, 8] m`, `B/L ∈ [0.07, 0.13]`, `T/L ∈ [0.045, 0.08]`. Each is meshed and CFD-solved in OpenFOAM, then converted to a PyTorch Geometric graph.

## Results

- Train R² (pooled, 32 hulls): **0.985**
- Held-out test R² (pooled, 8 hulls): **0.844**
- 7 of 8 test hulls score R² between 0.82 and 0.99.

One hull, `wigley_03`, degrades sharply (R² < 0). It sits at a corner of the sampled parameter space — the longest hull and among the most slender — which the training set under-represents. That's an extrapolation failure, not a bug: the expected limit of a data-driven surrogate is the boundary of the data it was trained on.

## Repo structure

```
openfoam/           OpenFOAM case template, generated hull geometries, per-hull CFD run dirs
  cases/wigley/      clean case template (0/, constant/, system/)
  geometries/batch/  generated hull STLs + manifest.csv (LHS parameters)
  runs/              per-hull CFD run directories (mesh + solve + VTK output)
src/foilnet/
  data/              mesh_to_graph.py — VTK surface -> PyG graph conversion
  pillars/mesh_gnn/  HullGNN model definition
  training/          training scripts (overfit sanity check, leave-one-out, full dataset)
scripts/             batch hull generation, CFD batch runner, graph conversion, visualization
data/processed/      converted graphs (wigley_NN.pt) and the trained checkpoint
reports/figures/     prediction visualizations
```

## Reproduce

```bash
# 1. Generate 40 hulls via LHS (Mac)
python3 scripts/generate_hull_batch.py --n 40

# 2. Mesh + solve every hull (inside the OpenFOAM 11 Docker container)
scripts/run_batch_cfd.sh

# 3. Convert CFD output to graphs (Mac)
python3 scripts/convert_batch_graphs.py

# 4. Train HullGNN with an 80/20 train/test split (Mac, CPU)
PYTHONPATH=src python3 src/foilnet/training/train_dataset.py

# 5. Visualize a prediction against CFD ground truth
PYTHONPATH=src python3 scripts/visualize_prediction.py wigley_09
```
